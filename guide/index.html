sea_of_colours

# download → install → play → beat the agent

A turn-based, fog-of-war strategy game about harvesting a hostile planet by night. You will have it running in about three minutes and be playing a full season against a heuristic bot on the fourth. Snowflake is optional and only needed later, when you want to play against — and then improve — the LLM agent.

[ START INSTALLING ↓ ] [ READ THE MANUAL ]

00 · What this is

The game, and the exercise

Two things ship in this repo: a game you play in a browser, and an LLM agent that plays it badly enough to be interesting. Your job at the hackathon is the second one.

The game in six lines §2 · §3
  • A planet is hidden under fog. Beneath it lie three substances — RED (precious), BLUE (fuel) and GREEN (worthless, and a liability).
  • You harvest only at night. A season is 7 nights, each exactly 21 hours long.
  • Each night you write a policy: a queue of orders — step, drop, probe, pick up — that execute in slot order once you transmit.
  • You see only what your units see. Probes light up a radius-4 disk and expire after 3 nights.
  • At dawn you enter orbit, where you spend credits on harvesters, repairs and weapons. Then your vault settles itself — everything you hoarded ships automatically.
  • Most points after seven nights wins.

That is the whole loop. Everything else — SNAPs, EMPs, chaff, echo vision, catapult lanes — is detail the manual animates far better than prose can.

Who you can play against
Opponent Needs What it is
RED_HARVEST_LITE nothing Heuristic bot with weapons switched off. Competent harvester, won't EMP or chaff you. Start here.
RED_HARVEST nothing The same bot with the full arsenal enabled. Considerably meaner.
V12 Snowflake PAT The LLM agent. Thinks in Snowflake Cortex, plays slowly, and is the thing you are here to improve.
The exercise

V12 is strong at reading the board and terrible at two specific things: it buys weapons and then never fires them, and it under-values BLUE. Both gaps are deliberate. Closing them — a purchasing heuristic for orbit, and a way to inject weapon plays into the agent's reasoning — is the hackathon. Details in 08 · Build.

01 · Install

Get it on your machine

Pure Python, no build step, no database. Five commands.

Prerequisites
Python 3.10+ Check with python3 --version. Anything from 3.10 onwards is fine; 3.13 is what this is developed against.
git Only if you clone rather than download a zip.
A browser Chrome, Edge, Safari or Firefox. No extensions needed.

No Snowflake account, no Docker, no Node. Those come later or not at all.

Step 1 · Fork it, then clone your fork
Fork first

Open the repo and press Fork. You now have your own copy at github.com/<you>/sea-of-colours-hackathon, and that is the one to clone. Your agent lives in your fork all day; at the end an organiser gathers everyone's forks to build the league.

Cloning this repo directly instead is the one setup mistake that costs real time, because nothing goes wrong until you try to publish — you can install, play and build an agent against the wrong remote perfectly happily, and only find out at the deadline. soc doctor checks it for you. 

# replace <you> with your GitHub username
$ git clone https://github.com/<you>/sea-of-colours-hackathon.git
$ cd sea-of-colours-hackathon
$ git remote add upstream https://github.com/sfc-gh-lgalan/sea-of-colours-hackathon.git
Access

The repo is private, so you need to be signed in to GitHub and given read access before the Fork button will work — ask the organiser if you get a 404. Prefer SSH? Use git@github.com:<you>/sea-of-colours-hackathon.git.

That upstream remote is how you take kit fixes during the day: git pull upstream main. You never push to it. Everything you push goes to origin, which is your fork.

Everything below assumes you are in the repo root — the folder containing run_web.py.

Step 2 · Virtual environment + dependencies 
$ python3 -m venv .venv
$ source .venv/bin/activate      # Windows: .venv\Scripts\activate
$ pip install -r requirements.txt

That pulls five packages — FastAPI, Uvicorn, httpx, requests and pytest. The Snowflake libraries are deliberately not in here; they are a separate, optional install covered in 05.

✓ Checkpoint. pytest -q should report roughly 938 passed, 4 skipped in a few seconds, with exactly one failure: test_heuristic_passes_known_scenarios[two_seams_choose_one]. That one is a known pre-existing bug in a heuristic eval, not your install. Anything else failing is worth investigating. The suite needs no network, no credentials and no Snowflake.

02 · First run

Start the server

One command, no environment variables. The server works out where to keep game state from what you actually have installed, and says so on the second line.

Run it 
$ python run_web.py
[soc] FastAPI starting
[soc] store backend: memory — sessions will not persist
[soc]   auto-detected memory: no Snowflake connection configured
INFO:     Uvicorn running on http://127.0.0.1:8000

Open http://127.0.0.1:8000.

Run this in your own terminal

Type it into a terminal window yourself. Do not ask an AI coding assistant to start the server for you — the server it launches belongs to that assistant's shell session, and when the session ends or the assistant moves on to the next task, the server is killed with it. Your game dies mid‑night and it looks exactly like the app crashing. Leave your own terminal open for as long as you want to play.

What that second line means

The server picks where game state lives by looking at what you actually have installed. With no Snowflake setup it uses memory — every session lives in the server process. That is the right answer for now: it costs nothing and the full game against either heuristic works. What you give up is keeping seasons across a restart, and with it the LLM agents, which the launcher offers only on a persistent backend so that every AI game can be replayed afterwards. Section 05 sets that up.

SOC_BACKEND=memory|file|snowflake forces the default; from v1.14 each game also picks its own in the launcher's STORAGE row. The badge in the bottom-right corner names the server default.

Something not right?

python scripts/quickstart_check.py checks your Python version, dependencies, backend, agent roster, Snowflake credentials and cloudflared, and prints the fix next to anything that fails. Add --network to also contact Snowflake, --tests to run the suite. Optional things report skip, not failure — a clean run means nothing is broken, not that you set up Snowflake.

✓ Checkpoint. You should see the title screen with Tutorial, Play, Multiplayer, Replay and Turn Lab. Hit Tutorial and pick Quick game — you are on the board against RED_HARVEST_LITE immediately, with no films. Skip to 04 if you'd rather start playing than read about the launcher.

03 · First game

Spawn a session

Quick game already did this for you — it spawns the exact setup below. Read on when you want a different map, more seats, or V12 in the other chair; hit Play on the title screen to get the launcher.

The launcher asks four blocks of questions, and the defaults are the right answer for a first game.

// new game
Block Leave at Note
# BOARD 40 × 28
7 nights		 The canonical competitive board and a full season. Drop LENGTH to 3 nights for a quick first pass.
# SEATS 2
P1 HUMAN
P2 RED_HARVEST_LITE 		You and one opponent, already the default. RED_HARVEST_LITE is the weapons-off bot — you should not get EMP'd before you know what a parcel is. Each seat can be renamed and recoloured here.
# VISIBILITY HIDDEN Fog of war. OPEN makes every seat omniscient — useful for watching two bots, wrong for playing, and never valid for comparing agents.
# STORAGE whatever is offered MEMORY is instant and forgets the season when the server stops; SNOWFLAKE keeps it, and is the only one that offers LLM seats — an AI game you cannot replay is one you cannot learn from. If Snowflake is greyed out, the row says which setup step is missing.

The line beside [ > SPAWN SESSION ] restates what you are about to create — check the storage word in it before you commit, because that is the one choice you cannot revise later.

You are now on night 1

The board is fogged, you have a couple of units and a credit balance, and the phase is planning. Nothing is ticking — the game waits for you.

05 · Snowflake

        
Wire up Cortex

        

          Only needed to play against or work on V12. Any
          Snowflake account works, including a fresh
          30-day trial. This is a
          token, not a deployment — no schema, no tables,
          no warehouse.
        


        

          Two different things, often confused
          

            (a) Running V12 needs a Programmatic Access Token
            so the agent can call Cortex inference. That is this section, and it
            is what nearly everyone wants.
          

          

            (b) Persisting games to Snowflake tables
            (SOC_BACKEND=snowflake) needs key-pair auth and a schema
            deploy. Different credential, different purpose — a PAT will
            not open a Snowpark session and a key pair will not authenticate a
            Cortex call. It is at the bottom of this section, and if you are
            here for the hackathon you want it too: the replay and turn-suite
            tooling reads persisted games.
          

        


        

          

            Step 1 · Generate a PAT
          

          
In Snowsight:

          

            Admin → Users & Roles → your user →
            Programmatic access tokens → Generate new token
          

          

            Copy the value immediately — Snowflake shows it exactly once.
          

        


        

          

            Step 2 · Let your role call Cortex
          

          

            

GRANT DATABASE ROLE SNOWFLAKE.CORTEX_USER TO ROLE <your_role>;

          

          

            On a fresh trial, ACCOUNTADMIN already has this. Cortex
            also has to be available in your region — see Snowflake's
            availability list.
          

        


        

          

            Step 3 · Point the game at your account
          

          

            The game reads your standard Snowflake connection —
            the same ~/.snowflake/connections.toml the Snowflake
            CLI, Cortex Code and the VS Code extension use. If you have ever
            run snow connection add, skip this step.
          

          
Otherwise create ~/.snowflake/connections.toml:

          

            

[soc]
account = "<your_account_identifier>"
token = "<the token from step 1>"

          

          

            Then point the game at it — this names one connection for
            the game only, leaving your shell default alone:
          

          

            

export SOC_SNOWFLAKE_CONNECTION=soc

          

          

            Prefer to keep the token out of a file? Set
            SNOWFLAKE_PAT in your shell instead and leave
            token out — the environment wins.
          

          

            Your account identifier is in Snowsight's bottom-left account
            selector, or in the URL:
            https://<account_identifier>.snowflakecomputing.com.
            If you would rather not keep the token in a file, drop the
            pat= line and export
            SNOWFLAKE_PAT in the shell you launch the server from
            instead — the env var wins.
          

        


        

          

            Step 4 · Smoke-test before you trust it
          

          

            

$ python - <<'PY'
from sea_of_colours.orchestrator_2.cortex_chat import CortexChatInvoker
inv = CortexChatInvoker(max_completion_tokens=20)
print("ready:", inv.is_ready())
print(inv.invoke("Reply with exactly the word: pong"))
PY

          

          

            ✓
            
              Checkpoint. ready: True and a reply containing
              pong. If you get that, V12 will run.
            
          

        


        

          

            Step 6 · Persist games to Snowflake
            about ten minutes · unlocks the iteration loop
          

          

            Everything above ran on the memory backend, which
            forgets a season the moment the server stops. That is fine for
            practice games, but the tooling you will use to actually improve
            your agent — replay_turn.py,
            turn_suite.py, advise_v12.py — reads
            games back off a persistent store, and the launcher only offers LLM
            seats on one for the same reason. This is that store.
          

          

            It authenticates with
            key-pair auth,
            not the PAT from step 1 — deliberately, so that wanting to
            play against V12 never silently starts writing to your account.
          

          

            

$ pip install -r requirements-snowflake.txt

# 1. generate an UNENCRYPTED key pair (-nocrypt matters)
$ openssl genrsa 2048 | openssl pkcs8 -topk8 -inform PEM -out rsa_key.p8 -nocrypt
$ openssl rsa -in rsa_key.p8 -pubout -out rsa_key.pub

# 2. print the key body alone — no BEGIN/END lines, no newlines
$ awk 'NR>2 {print prev} {prev=$0}' rsa_key.pub | tr -d '\n'

          

          

            Paste that single line into Snowsight:
          

          

            

ALTER USER <your_username> SET RSA_PUBLIC_KEY='<the one line>';

          

          

            

# 3. add to your connection:  user = "..."  private_key_file = "/path/rsa_key.p8"

$ python scripts/deploy_soc_schema.py --dry-run
Target: SOC_HACKATHON_DB.SEA_OF_COLOURS (warehouse SOC_HACKATHON_WH)

$ python scripts/deploy_soc_schema.py
$ python scripts/quickstart_check.py

# the command to use from here on — see the note below
$ SOC_BACKEND=snowflake python run_web.py --no-reload
[soc] store backend: snowflake (SOC_HACKATHON_DB.SEA_OF_COLOURS)

          

          

            Start it this way, in your own terminal
            

              SOC_BACKEND=snowflake turns Snowflake from a
              preference into a requirement. Auto-detect is deliberately
              forgiving — if anything about the Snowpark path is
              unusable it hands you a memory server instead,
              and you discover that an hour later when the season is gone
              and the LLM seats never showed up. Explicit is strict: the
              server refuses to start and tells you what to fix.
            

            

              --no-reload because auto-reload is on by
              default, and a file save restarts the process —
              dropping any agent turn in flight and resetting the
              per-process submit lock. Mid-night, that reads to players as
              the game hanging.
            

            

              Run it in a terminal you own and leave it running. A server
              started by an AI coding agent is a child of that agent's
              shell and dies with it, which looks exactly like a crash.
            

          

          

            Seasons disappeared from the picker?
            

              The Snowpark auth token expires after a few hours. Today the
              failure is silent — you get fewer games rather than an
              error, and ASK V12 greys out as if you were on a memory
              backend. Restart the server.
            

          

          

            If auth fails later
            

              JWT token is invalid is nearly always the public key:
              Snowflake wants the base64 body only, so a surviving
              -----BEGIN----- line or a stray newline breaks it.
              Re-run the awk one-liner and
              ALTER USER again. A passphrase error instead means
              the key was generated encrypted — regenerate with
              -nocrypt.
            

          

          

            Once private_key_file is on your connection the
            server picks the Snowflake backend on its own — no env var. Set
            SOC_BACKEND=snowflake explicitly if you'd rather the
            server refuse to start than quietly fall back to
            memory when something's wrong.
          

          

            The database, schema and an XSMALL auto-suspending warehouse are
            created if absent, so this works on a brand-new account. Names are
            hackathon-scoped by default so they cannot collide with an existing
            install; override with SOC_DATABASE /
            SOC_SCHEMA / SOC_WAREHOUSE.
          

          

            Seasons accumulate
            

              Starting a new game never deletes an old one — each is a
              fresh session alongside the last, and they all stay in the season
              picker. Wiping exists but you have to ask for it
              (run_season.py --wipe-first). Still worth checking
              --dry-run points where you think it does before
              deploying into an account with other things in it.
            

          

          

            You can still play fast
            

              Storage is chosen per game. The launcher's
              STORAGE row offers Snowflake or Memory, and
              Quick game on the title screen always uses Memory —
              so having a schema deployed never means every practice game costs
              a warehouse round-trip per move.

07 · Multiplayer

        
Play someone in the room

        

          Up to four seats, each in its own browser — laptops, phones,
          across the table or across the internet.
        


        

          

            Host a game
          

          

            

# recommended before you host — keeps one address all session
$ brew install cloudflared

# then click MULTIPLAYER on the title screen
$ python run_web.py

          

          

            MULTIPLAYER opens a public tunnel, moves your
            browser onto it and spawns the session; you then hand out one QR
            per seat and they work from anywhere. You can host with nothing
            installed — the fallback provider is plain ssh
            — but its free address changes after a few minutes, which
            kills the links mid-game, so cloudflared is worth
            the thirty seconds.
          

          

            Why there are two providers
            

              cloudflare goes first because its address lasts the
              whole session. localhost.run sits behind it because
              it needs no install at all, and because locked-down networks
              filter outbound traffic unevenly — some drop the SSH the
              fallback needs, others don't — so between the two almost
              every network is covered. The server doesn't guess which:
              it starts the first provider, waits for the address it printed
              to become resolvable here, and falls through if it never does.
              /api/tunnel/status says which one won.
            

            

              If the links stop working mid-game
              A tunnel can drop. The server notices and restarts it, but a
              restart means a new address, so the QRs you already
              handed out are dead. Look at the terminal running
              run_web.py: it prints the new URL with
              NEW ADDRESS beside it. That's the only place it
              can tell you — everyone's browser, yours included, is
              sitting on an address that no longer exists. Re-share and
              carry on; the game itself is untouched, because it lives on
              the server and not in the link.
            

            

              That wait is deliberate, and it's the one thing to know if you
              ever debug this: a tunnel hostname doesn't exist for a second or
              two after the client prints it, and a DNS lookup in that gap gets
              cached as "no such name" for thirty minutes. Checking
              impatiently is how you break the link you're checking — so
              if your own browser can't open the URL, get a fresh one rather
              than poking at the old one.
            

          

          

            The docs ride along: <url>/guide/,
            <url>/manual/ and
            <url>/manual/agent.html all work from the
            tunnel origin, so a first-timer you invite can read the rules
            without cloning anything.
          

          

            Two rules that keep sync intact
            

              No auto-reload during a party. The cross-player
              submit lock is per-process, so a stray file save doesn't hiccup
              — it resets everyone's season. Start with
              python run_web.py --no-reload if you'll be editing
              code while others are playing.
            

            

              Pick your storage when you spawn. A
              MEMORY game dies with the process; choose
              SNOWFLAKE in the launcher's STORAGE row if the match
              should survive a restart (see 05).
              Anonymous tunnels also get a new random address every restart, so
              re-share the links if you bounce the server.
            

          

          

            Full detail, including the phone UI and firewall troubleshooting, is
            in docs/MULTIPLAYER.md.
          

        

      


      
      

        
08 · Build

        
Make V12 better

        

          Play a season against it first. You will spot the gaps yourself before
          anyone points them out — that is the intended order.
        


        

          

            The two known gaps
          

          
    
            
  1. 
              It buys weapons and never uses them. V12 will happily spend
              credits on EMPs and chaff in orbit, then plan a night as though
              its own arsenal does not exist. Nothing in its reasoning path
              turns a held weapon into an order.
            
    2. 
            
  2. 
              It under-values BLUE. The value model treats blue as an
              afterthought, so V12 tends to run its fuel economy close to the
              edge and pass up good blue for mediocre red.
            
    3. 
          

          

            Two natural pieces of work, and they compose: a purchasing heuristic
            that buys the right weapon for the board, and an injection
            point that lets the agent choose to fire it.
          

        


        

          Read this first
          

            The agent & harness guide
            takes one real V12 turn apart stage by stage — what the
            agent is shown, how the prompt is assembled, what comes back,
            and how it is sanitised into legal moves. An hour there will
            save you a day of reading the harness cold.
          

        


        
Mint your own agent

        

          One command. It copies V12 into a directory of your own and renames
          its identity, so your turns are attributed to you rather than to
          V12.
        


        

          

            
            mint your agent
            
          


python scripts/soc.py new --team redwatch --name reaper \
    --participants "Ada Lovelace, Grace Hopper"

        


        

          Restart the server and REDWATCH_REAPER is in the NEW
          GAME dropdown, ready to play against V12. Name it
          <team>_<agent> — the label ends up in
          the audit trail and on the scoreboard, and a room full of agents
          called reaper helps nobody. Everyone at the table goes
          in --participants: the league is the day's public
          record, and an entry that names nobody cannot be credited.
        


        

          There is no register to sign
          

            Minting writes an agent.json in your new directory
            and that is the registration — the kit finds your
            agent by scanning for those files at startup. You do not edit a
            shared registry, which is exactly why a room of teams can all be
            minting agents at once without treading on each other.
          

        


        

          Don't edit V12 in place
          

            V12 is the control in your experiment. Change it directly and
            you can no longer answer “is my agent better?”,
            because there is nothing left to compare against — and
            matches between teams stop being like-for-like. The fork costs
            a second.
          

        


        

          Ask V12 mid‑game
          

            On a Snowflake game, the night orders panel grows an
            ◇ ask V12 button. It runs the shipped agent's full
            think‑and‑plan pass over your board and hands
            back what it would do — its reasoning on one tab, the
            compiled orders on the other. Hover show on map to see the
            orders on the board, numbered by the hour each would fire, and
            adopt plan drops them into your queue so you can edit them
            before you transmit. It never plays your turn.
          

          

            Useful two ways: as a second opinion while you learn the game,
            and as a way to watch your fork's reasoning change as you edit
            it. One caveat — because V12 is not actually playing your
            seat, it keeps no memory between asks. Each answer reasons from
            the position in front of it, where the same agent playing an
            opposing seat carries its journal from night to night.
          

        


        

          Your fork ships with its own
          README:
          the turn pipeline, what the debug card shows, where plays come
          from, and both gaps above with the exact files and constants.
          Start there. The
          orchestrator
          README covers the harness contract if you would rather write
          an agent from scratch than fork one.
        


        

          

            Where to look
            sea_of_colours/orchestrator_2/harnesses/tabula_v12/
          

          

            

              harness.py
              Turn entry point. Follow it once, top to bottom, before changing anything.
            

            

              orbit.py
              
                Orbit phase. Currently delegates straight to the shared
                heuristic — this is where a purchasing strategy goes.
              
            

            

              prompt.py
              The prompt is built in Python each turn. Edit it and the next turn uses it; there is no redeploy.
            

            

              value_pyramid.py
doctrine.py		
              How tiles are scored and how priorities are stated. The blue problem lives here.
            

            

              ENGINE_INTERFACE.md
              The boundary the harness must obey. Read before you reach past it.
            

          

          

            V12 is self-contained — it imports nothing from any other
            harness, so you can read and change it without tracing into
            neighbouring code.
          

        


        

          

            House rules for changes
          

          
    
            
  • 
              RULEBOOK.md is canonical. If the code
              and the rulebook disagree, the rulebook wins — or the
              rulebook needs updating, and you should say so.
            
    • 
            
  • 
              Score your change with
              run_matchup_v12.py on fixed seeds. A harness change
              that feels smarter and loses is common.
            
    • 
            
  • 
              pytest -q before you call it done.
            
    • 
          

        


        

          

            Publishing it
          

          

            An agent that only exists on your laptop does not compete. Push it
            to your fork, and push often — whatever is on your fork when
            the organiser collects is what plays.
          

          

            

$ python scripts/soc.py push

          

          

            That commits your agent's directory and nothing else, then pushes
            to origin — your fork. It refuses if you have
            changed anything outside your own directory, because only your
            directory travels to the league: a fix you made to the engine
            would simply be missing there, and your agent would behave
            differently than it does at your desk.
          

          

            To hand work-in-progress to a teammate without publishing
            anything, use soc share and they run
            soc grab on the file. That is for the ten-minute
            loop; soc push is for the record.
          

          

            Pushing is not entering
            

              Your fork is where your agent lives. The league is assembled at
              the end of the day by an organiser running
              soc collect, which lifts each agent out of each
              fork into one staging area. Nothing you push lands in anyone
              else's repo, and nobody else's push can break yours.

When it doesn't work


        

          

            Symptom → cause
          

          

            

              You see
              What it means
            

            

              ModuleNotFoundError: snowflake.snowpark
              
                You set SOC_BACKEND=snowflake without the
                optional deps: pip install -r
                requirements-snowflake.txt, or unset the variable and
                let the server auto-detect.
              
            

            

              
                SOC_BACKEND=snowflake was requested but the store
                could not be opened
              
              
                An explicit request is strict on purpose — better to
                stop than to write your season somewhere you didn't mean.
                The line under it names the fix.
              
            

            

              Game vanished after a restart
              
                You are on memory. Check the boot line or the
                badge in the bottom-right; 05 makes
                seasons durable.
              
            

            

              Spawning a V12 game is refused
              
                The credential preflight found no PAT or no account. The message
                names which. See 05.
              
            

            

              ready: False in the smoke test
              
                No PAT, or no account on the connection that got
                resolved. Run python scripts/soc.py doctor —
                it prints the exact file and section it read, which settles
                “no credentials” versus “the wrong one of
                my five connections”.
              
            

            

              V12 turns take forever
              
                Expected. It is running real inference over the network. Shorten
                the season to 3 nights while iterating.
              
            

            

              Address already in use
              
                Something is already on port 8000 — usually your own
                server from earlier. Add --replace to stop it and
                take over, or --port 8001 to run both. Nothing to
                hunt for: --replace refuses unless the port
                answers as Sea of Colours, so it cannot take out the unrelated
                thing you had there.
              
            

            

              Edited a file, nothing changed
              
                Static assets are served no-cache from disk, so JS/CSS need only
                a hard refresh (Cmd-Shift-R). Python changes need a server
                restart — run_web.py auto-reloads for you
                unless you started it with --no-reload, which is
                what the Snowflake command above recommends. Re-run that same
                command with --replace and it will stop the old
                server for you.
              
            

            

              git clone returns 404
              
                The repo is private. GitHub returns 404 rather than 403 for
                repos you cannot see, so this usually means you are not signed
                in, or have not been given read access yet. Ask the organiser.
                Check the URL has your username in it — you
                clone your fork, not the original.
              
            

            

              
                soc push says origin is not
                yours
              
              
                You cloned the original repo instead of forking it first.
                Nothing is lost and nothing needs re-doing: soc
                push prints the two commands that point this clone at
                your own fork, and your work comes with it.
              
            

            

              Pushing says permission denied
              
                Same cause as above. You only ever have write access to your
                own fork — nobody, including you, pushes to the repo the
                event runs from.
